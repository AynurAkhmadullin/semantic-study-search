# Semantic Study Search

Семантический поиск по учебным материалам на основе предобученной модели
[`intfloat/multilingual-e5-small`](https://huggingface.co/intfloat/multilingual-e5-small).
Проект для проектного практикума магистратуры «Инженерия искусственного интеллекта».

Автор проекта подготавливает общую библиотеку материалов. Пользователь задаёт вопрос
через веб-интерфейс Streamlit или API FastAPI и получает подходящие фрагменты
с названием документа и ссылкой на источник.
Векторы материалов вычисляются при подготовке библиотеки и сохраняются на диск;
при поиске вычисляется только вектор запроса.
Обучение и дообучение модели не предусмотрены.

Слабые совпадения отбрасываются по калиброванному порогу сходства. Если ни один
фрагмент не прошёл фильтр, приложение сообщает об отсутствии достаточно близких
результатов. Порог уменьшает нерелевантную выдачу, но не гарантирует наличия ответа:
вопросы, близкие к теме материалов, могут проходить фильтр без нужного объяснения.

В комплект входит демонстрационная библиотека: текстовые выдержки из восьми
русскоязычных разделов курса Hugging Face о NLP, трансформерах, токенизации
и документировании моделей. Материалы распространяются по Apache-2.0;
источники, версия курса и сведения об изменениях находятся в
`src/semantic_study_search/resources/corpus.json` и `NOTICE.txt`, текст лицензии —
в `LICENSE.huggingface-course.txt` в том же каталоге.
В каталоге `examples` находятся ещё два демонстрационных текста проекта
и список источников для их добавления в библиотеку.

## Требования

- Git.
- [uv](https://docs.astral.sh/uv/getting-started/installation/) версии `0.11.29`
  или новее; для текущего окружения используется `0.11.29`.
- Python **3.13**: `uv` может загрузить его автоматически по файлу `.python-version`.
- Доступ к GitHub, PyPI и `download.pytorch.org` для первой установки.
- Доступ к Hugging Face для первоначального скачивания модели; её веса занимают
  около 471 МБ, дополнительно загружаются токенизатор и настройки.

Основные целевые платформы — Windows x86-64 для разработки и Linux x86-64 для облака.
На обеих платформах PyTorch берётся из официального CPU-индекса, без CUDA-зависимостей.
Это задано в `pyproject.toml` по
[инструкции uv для PyTorch](https://docs.astral.sh/uv/guides/integration/pytorch/).

## Инструкция установки

Установите Git и uv, затем выполните в PowerShell, Bash или другом терминале:

```shell
git clone https://github.com/AynurAkhmadullin/semantic-study-search.git
cd semantic-study-search
uv sync --locked --all-extras
```

Команда создаёт `.venv`, устанавливает пакет проекта в редактируемом режиме,
все группы приложения и инструменты разработки. Версии берутся из `uv.lock`.
Установка ML-библиотек требует скачивания крупных пакетов, включая PyTorch.
Вручную активировать окружение для команд `uv run` не требуется.

Если проект уже подготовлен в `project_workshop/semantic-study-search`, запускайте
`uv sync` из этой вложенной папки. Повторное клонирование внутрь неё не требуется.

Проверка установки пакета:

```shell
uv run --locked --all-extras python -c "import semantic_study_search; from importlib.metadata import version; print(version('semantic-study-search'))"
```

Ожидаемый результат: `0.1.0`.

Проверка доступности основных библиотек без скачивания весов модели:

```shell
uv run --locked --all-extras python -c "import fastapi, httpx, numpy, sentence_transformers, streamlit, torch, uvicorn; print('Dependencies OK')"
```

Ожидаемый результат: `Dependencies OK`. Эти команды проверяют установку пакета
и основных библиотек без скачивания весов модели.

Подготовьте демонстрационный индекс из восьми встроенных материалов и двух
примеров проекта, выполнив команду из каталога репозитория:

```shell
uv run --locked --all-extras semantic-study-index --include-demo --manifest examples/library.json --cache-dir .cache/huggingface/hub
```

Первый запуск скачивает закреплённую версию `intfloat/multilingual-e5-small`.
Модель работает на CPU. Индекс сохраняется в `data/processed/library`: метаданные
и тексты — в SQLite, векторы — в `vectors.npy` внутри каталога версии.

Запуск поиска по сохранённому индексу:

```shell
uv run --locked --all-extras semantic-study-search "Зачем нужна маска внимания?" --cache-dir .cache/huggingface/hub
```

Команда загружает готовые векторы и выводит до пяти подходящих фрагментов
с названиями документов, ссылками и косинусным сходством.
Значение сходства не является вероятностью правильного ответа.
Порог можно задать через `--min-score число`; значение `-1` отключает фильтрацию.
Без параметра используется значение из `resources/relevance_policy.json` внутри пакета.

После скачивания можно использовать тот же кэш без сети:

```shell
uv run --locked --all-extras semantic-study-search "Чем кодировщик отличается от декодировщика?" --cache-dir .cache/huggingface/hub --offline --top-k 3
```

Параметр `--json` включает машиночитаемый вывод. Чтобы выбрать другое расположение
индекса, передайте одинаковый `--index-dir путь/к/индексу` обеим командам.
Справка доступна через `semantic-study-index --help` и `semantic-study-search --help`.
Кэш модели и индекс сохраняются между запусками; сама модель загружается в память
при каждом запуске команды поиска.

Для расширения библиотеки используйте готовый пример списка источников:

```shell
uv run --locked --all-extras semantic-study-index --include-demo --manifest examples/library.json --cache-dir .cache/huggingface/hub --offline
```

Команда объединяет восемь встроенных документов и два примера проекта.
В списке источников каждый файл описывается так:

```json
{
  "schema_version": 1,
  "documents": [
    {
      "id": "lesson-1",
      "title": "Название учебного материала",
      "source_url": "https://example.org/materials/lesson-1.pdf",
      "path": "materials/lesson-1.pdf"
    }
  ]
}
```

Пути `path` отсчитываются от расположения JSON-файла. Поддерживаются TXT и Markdown
в UTF-8, а также PDF с текстовым слоем. Страницы PDF получают отдельные идентификаторы
и ссылки с номером страницы. PDF под паролем отклоняются; страницы без текста
пропускаются с сообщением, а полностью нетекстовый PDF отклоняется.
OCR не выполняется. Извлечение текста реализовано через
[pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html).

Параметры `--manifest` и `--corpus` можно повторять, объединяя файлы и готовые
JSON-корпуса. Идентификаторы документов должны быть уникальны. Каждый запуск
подготовки задаёт **полный состав** библиотеки: `--include-demo` добавляет встроенные
материалы к указанным источникам. Без источников используется встроенный корпус.

При совпадении корпуса и настроек команда подготовки использует готовый индекс
без загрузки модели. При изменении текстов, источников или параметров выполняется
полная пересборка. Размер фрагментов задаётся через `--chunk-tokens`, перекрытие —
через `--overlap`; значения по умолчанию — 320 и 48 токенов.
Для принудительной пересборки, в том числе повреждённого индекса, добавьте `--force`.

Для разового поиска с вычислением векторов в памяти сохранён прежний режим:
`semantic-study-search "вопрос" --corpus путь/к/corpus.json`.

Для запуска веб-приложения откройте **два терминала** в корне репозитория.
В первом запустите API, предварительно подготовив индекс указанной выше командой.
Пример для PowerShell с уже скачанной моделью:

```powershell
$env:SSS_MODEL_CACHE = "$PWD/.cache/huggingface/hub"
$env:SSS_OFFLINE = "1"
uv run --locked --all-extras uvicorn semantic_study_search.api.app:app --host 127.0.0.1 --port 8000
```

API загружает модель и индекс один раз при старте процесса. Дождитесь сообщения
`Application startup complete`, затем проверьте
[готовность сервиса](http://127.0.0.1:8000/health): ожидается статус `ready`.
Если весов ещё нет в кэше, задайте `SSS_OFFLINE=0` для их скачивания.
После пересборки библиотеки перезапустите API, чтобы загрузить новую версию индекса.

Во втором терминале запустите интерфейс:

```powershell
$env:SSS_API_URL = "http://127.0.0.1:8000"
uv run --locked --all-extras streamlit run src/semantic_study_search/ui/app.py --server.address 127.0.0.1 --server.port 8501
```

Откройте [приложение](http://127.0.0.1:8501), введите вопрос и нажмите «Найти».
Интерфейс показывает размер библиотеки, фрагменты, сходство и ссылки на источники.
Длинный фрагмент можно раскрыть целиком. Интерфейс обращается к API по HTTP;
модель в процессе Streamlit не загружается.
Оба процесса останавливаются сочетанием `Ctrl+C` в соответствующем терминале.

Переменные окружения задаются до запуска соответствующего процесса:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `SSS_INDEX_DIR` | `data/processed/library` | Каталог индекса для API, относительно рабочей папки |
| `SSS_MODEL_CACHE` | Стандартный кэш Hugging Face | Каталог весов для API; используйте тот же путь, что и `--cache-dir` при подготовке |
| `SSS_OFFLINE` | `0` | Только локальные веса: `1` или `true`; разрешить скачивание: `0` или `false` |
| `SSS_MIN_SCORE` | Около `0.82066`, из `resources/relevance_policy.json` | Нижняя граница сходства фрагментов; число от -1 до 1, `-1` отключает фильтр |
| `SSS_API_URL` | `http://127.0.0.1:8000` | Адрес API для интерфейса |

Файл `.env` автоматически не читается. В Bash переменные задаются через
`export SSS_MODEL_CACHE="$PWD/.cache/huggingface/hub"` и аналогично для остальных.

Методы API доступны в [интерактивной документации Swagger](http://127.0.0.1:8000/docs):

| Метод | Путь | Результат |
| --- | --- | --- |
| `GET` | `/health` | Готовность поиска и количество документов и фрагментов |
| `POST` | `/search` | Вопрос и список результатов с текстами, источниками и сходством |

Пример запроса в PowerShell:

```powershell
$body = @{ query = "Зачем нужна маска внимания?"; top_k = 5 } | ConvertTo-Json
Invoke-RestMethod -Uri http://127.0.0.1:8000/search -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

Вопрос должен содержать от 1 до 2000 символов после удаления крайних пробелов
и помещаться в 512 токенов вместе с префиксом модели. `top_k` — целое число
от 1 до 20, по умолчанию 5. Ошибки ввода возвращают HTTP 422, отсутствие готового
поиска или занятость модели — 503, внутренняя ошибка поиска — 500.
Поиск обрабатывает один вопрос за раз; при занятости можно повторить запрос.
При ошибке загрузки индекс и модель не восстанавливаются автоматически:
исправьте причину по журналу сервера и перезапустите API.

Пустая выдача — штатный ответ HTTP 200 с `results: []`. Количество результатов
может быть меньше `top_k`, поскольку каждый фрагмент должен пройти порог.
Значение по умолчанию подобрано для десяти демонстрационных документов и текущей
версии модели. Для другой библиотеки, модели или разбиения его нужно проверить
заново. Изменение `SSS_MIN_SCORE` применяется после перезапуска API.

## Зависимости

| Группа | Состав | Назначение |
| --- | --- | --- |
| `ml` | NumPy, Sentence Transformers, PyTorch, pypdf, markdown-it-py | Модель, поиск и импорт файлов |
| `api` | FastAPI, Pydantic, Uvicorn | HTTP-сервис |
| `ui` | Streamlit, HTTPX, Pydantic | Интерфейс, обращения к API и проверка ответов |
| `dev` | pytest, pytest-cov, HTTPX, Ruff | Тестирование, API-клиент для тестов и проверка кода |

Группа `dev` устанавливается по умолчанию. При разработке используйте
`uv sync --locked --all-extras` и `uv run --locked --all-extras ...`.
`--all-extras` сохраняет в окружении все три группы приложения.
SQLite доступен через стандартный модуль Python `sqlite3`; отдельный сервер БД не нужен.

Для отдельных компонентов можно устанавливать только нужные зависимости:

```shell
# Сервер: модель и API
uv sync --locked --extra ml --extra api --no-dev

# Интерфейс
uv sync --locked --extra ui --no-dev
```

Эти команды изменяют состав текущего окружения. Вернуться к окружению разработчика:
`uv sync --locked --all-extras`.

Зависимости описываются в `pyproject.toml`, точные версии и хеши — в `uv.lock`.
Оба файла хранятся в Git. При изменении списка зависимостей обновляйте lock-файл
командой `uv lock`; обычная установка выполняется с `--locked`.
Это соответствует [модели работы uv с проектами](https://docs.astral.sh/uv/guides/projects/).
